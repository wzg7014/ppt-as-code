# 05 - 迭代策略与决策框架

## 迭代的核心原则

**不要追求一次到位，要追求快速收敛。**

一个页面从零到满意，典型的迭代路径是：

```
方向探索（1-2 轮）→ 风格确定（1 轮）→ 细节微调（1-3 轮）→ 定稿
```

## 迭代决策树

生成 3 张候选图后，按以下流程决策：

```
3 张候选图生成完毕
    │
    ├─ 3 张都不行
    │   └─→ Prompt 方向有问题
    │        ├─ 是风格问题？ → 做多方案对比（3 种风格各 1 张）
    │        ├─ 是内容问题？ → 重新理解需求，修改 Prompt 核心内容
    │        └─ 是布局问题？ → 更换/添加参考图
    │
    ├─ 方向对但细节不满意
    │   └─→ 微调 Prompt，新建 gen_v2.py
    │        ├─ 文字位置偏了 → 精确描述位置（"居中偏上1/3处"）
    │        ├─ 颜色不对 → 逐字指定颜色
    │        ├─ 某元素太突出/太弱 → 调整描述的篇幅和优先级
    │        └─ 缺少某个元素 → 在 Prompt 中增加该元素的描述
    │
    ├─ 1 张很好，2 张一般
    │   └─→ 选定好的那张 → 确认结束 → /done
    │
    └─ 想融合 A 的布局 + B 的色调
        └─→ 把 A 作为参考图，在 Prompt 里描述 B 的色调 → 新建 gen_v3.py
```

## 探索阶段：多方案对比

当完全不确定风格方向时，**先花一轮做方向探索**：

```python
# 3 种风格，每种只生成 1 张
PROMPTS = {
    "风格A_实体破冰": "...",
    "风格B_光芒凝聚": "...",
    "风格C_裂纹构图": "...",
}
```

- 3 种风格各 1 张 = 3 张图 = 3 次 API 调用
- 比"一种风格生成 3 张，不行再换"更高效
- 确定方向后，再对选中的风格生成 3 张做细化

## 微调阶段：参考图 + 增量描述

一旦大方向确定，后续迭代用"参考图 + 增量修改"策略：

```
以附带的参考图为基础，保持相同的整体风格。
只做以下调整：
1. 把标题从"X"改为"Y"
2. 底部金句颜色从白色改为金色
3. 其他所有元素保持不变
```

**关键：修改量越小，结果越可控。**

## 什么时候该停止迭代

- **已经满足需求** — 80 分就够了，不要追求 100 分
- **边际收益递减** — 第 5 轮迭代只比第 4 轮好一点点，就该停了
- **文字位置问题** — AI 对文字排版的控制有极限，最后在 PPT 软件中手动微调更快
- **3 轮以上没有实质进展** — 换思路，而不是死磕同一个方向

## 常见迭代路径

### 路径 A：一步到位（最理想）

```
gen.py（v1/v2/v3）→ 选定 v2 → /done → 提交
```
迭代：1 轮。参考图好 + 只需微调文字的页面常这样。

### 路径 B：方向对，微调 1-2 轮（最常见）

```
gen.py（3张）→ 方向对，文字位置偏了
→ gen_v2.py（3张）→ 选定 v2_v3 → /done → 提交
```

### 路径 C：方向探索 + 细化（中等复杂）

```
gen_风格对比.py（3种风格各1张）→ 选定风格B
→ gen_风格B_v2.py（3张）→ 基本满意但主体太小
→ gen_风格B_v3.py（3张）→ 选定 → /done → 提交
```
迭代：3 轮（探索 1 + 细化 2）。

### 路径 D：大幅探索（较复杂）

```
gen_v1.py（3张）→ 都不行
→ gen_三方案.py（3种方案各1张）→ 方案A接近
→ gen_方案A优化.py（3张）→ 方向对但缺数据元素
→ gen_补数据.py（3张）→ 选定 → /done → 提交
```
迭代：4-5 轮。

## 成本意识

每张图有 API 调用成本。参考：

- 每张约 0.16 元（Gemini 4K 分辨率）
- 每轮 3 张 = 0.48 元
- 一页 3 轮迭代 = 1.44 元
- 15 页 PPT ≈ 15-25 元

成本很低，不用过度节省，但也不要无意义地反复生成。**先在 Prompt 层面想清楚，再调 API。**
